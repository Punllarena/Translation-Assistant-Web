# Contributing

Thanks for helping. This guide covers the local setup, the checks CI runs, and the conventions the
code follows. For how the system fits together, read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
first.

## Development setup

### With Docker (recommended)

```bash
docker compose --profile dev up      # SPA http://localhost:5173, API http://127.0.0.1:8000/docs
```

The `dev` image (Python with the `dev` and `mecab` extras, Node 24, Playwright's Chromium)
bind-mounts the checkout, so edits reload live. File watching polls, because bind mounts from
Windows and macOS deliver no events. `web/node_modules` lives in a Linux-only named volume and is
reinstalled when `package-lock.json` changes.

Stop the production API first (`docker compose stop api caddy`): each API process runs the job
worker, and a starting one fails the jobs the other is running.

### Without Docker

Needs Python 3.12+, Node 24, and Postgres 16 (`docker compose up -d postgres` binds one to
127.0.0.1:5432).

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,mecab]"

# The app reads .env itself and refuses the .env.example placeholder key:
cp .env.example .env
sed -i "s|^TA_SECRET_KEY=.*|TA_SECRET_KEY=$(python -c 'import secrets; print(secrets.token_urlsafe(48))')|" .env

alembic upgrade head
uvicorn api.main:app --reload                 # API on http://127.0.0.1:8000/docs
cd web && npm install && npm run dev          # SPA on http://localhost:5173, /api proxied
```

Spellcheck needs enchant and an English dictionary (on Debian/Ubuntu: `libenchant-2-2
hunspell-en-us`).

## Checks

CI (`.github/workflows/ci.yml`) runs all of these on every push and pull request. Run them before
opening a PR.

| Check                        | Docker                                                         | Local                     |
|------------------------------|----------------------------------------------------------------|---------------------------|
| Lint                         | `docker compose run --rm tools ruff check .`                   | `ruff check .`            |
| API tests                    | `docker compose run --rm tools pytest`                         | `pytest`                  |
| Web unit tests               | `docker compose run --rm tools sh -c "cd web && npm test"`     | `cd web && npm test`      |
| Web build                    | `docker compose run --rm tools sh -c "cd web && npm run build"` | `cd web && npm run build` |
| End-to-end (Playwright)      | `docker compose run --rm tools sh -c "cd web && npm run e2e"`  | `cd web && npm run e2e`   |
| Generated API client current | `docker compose run --rm tools sh -c "cd web && npm run gen:api"` | `cd web && npm run gen:api` |

Run one test with `pytest tests/test_auth.py::test_name`.

- **Test database.** `pytest` uses `ta_test` and **drops and recreates it every run**; it refuses any
  database name not ending in `_test`. Set `TA_DATABASE_URL` only to point at a different Postgres.
- **E2E.** Needs the venv active (with the `mecab` extra) and Postgres up. It resets the `ta_e2e`
  database once per run and uses ports 8001 (API) and 5174 (SPA). The first run needs
  `cd web && npx playwright install chromium`.
- **Generated client.** After any API schema change, run `npm run gen:api` and commit
  `web/src/api/schema.d.ts`. CI fails if it is stale.

## Code conventions

- **Routers** are built with `api_router()`. Handlers `flush()`, never `commit()`; the route commits.
- **Tenancy.** Fetch user-owned rows by id through `scoped()` in `api/deps.py` (404 for another
  user's rows). List endpoints filter by `user_id` inline.
- **Migrations** are autogenerated (`alembic revision --autogenerate`) and every model is imported in
  `api/models/__init__.py`. Fix the model and regenerate rather than hand-editing a revision.
- **Config** comes from the environment only (`TA_` prefix, `api/config.py`). No config files.
- **Size.** Keep each Python module under roughly 400 lines.
- **External services** (MT backends, WordPress) take an injected `httpx` client; tests use
  `httpx.MockTransport` fixtures and never call live endpoints.
- **Jobs in tests.** Tests set `TA_RUN_JOBS_WORKER=false` and drive jobs with `jobs.run_next()`.
- **Styles** use the tokens in `web/src/styles/tokens.css`, never literal colours.
- **E2E seeds.** Each Playwright spec owns its rows in `tools/e2e_seed.py`; seed names must not
  contain "E2E chapter", and glossary phrases a spec adds must occur only in its own chapters.
- **Lint** is ruff with `select = ["E", "F", "I", "B", "UP"]`, `B008` ignored (FastAPI's
  `Depends()` idiom). Alembic revisions are exempt from `E501` only.

## Pull requests

1. Branch from `main`.
2. Keep each PR to one change; larger features start with a spec in `docs/superpowers/specs/` and a
   plan in `docs/superpowers/plans/`.
3. Use [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`,
   `chore:`, with an optional scope such as `fix(e2e):`).
4. Make sure every check above passes, and add tests for new behaviour.
5. Record deferred work in [docs/TODO.md](docs/TODO.md) rather than leaving it in code comments.

Security issues go through [SECURITY.md](SECURITY.md), not public issues.
