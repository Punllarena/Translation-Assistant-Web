# Syosetu heading volumes: which headings start a volume, regrouping, merging

Date: 2026-10-21 · Status: draft for review

## Why

Fetching from syosetu now turns every `p-eplist__chapter-title` heading into a volume
(`api/fetch_job.py`, hidden key `volumes.syosetu_group`). Syosetu has only one heading level, so
authors fake a second one with a leading symbol. n0280z alternates `★` (a story day, often 1–3
chapters) and `◇` (an arc inside the day): 98 headings over 1,483 chapters, so a full fetch makes
98 mostly tiny volumes plus one 686-chapter `★ 後日談シリーズ`. Choosing `★` as the volume
boundary gives about 20 volumes (the days, the 番外編 episodes, 後日談), which is how the owner
wants to read it.

The owner chose (2026-10-21) three things:

1. **Pick which heading marker starts a volume**, per series (option 1).
2. **Off**: no volumes from headings for a series (option 4), as one value of the same setting.
3. **Merge volumes**: tick several volumes and merge them at once (option 3), for every series.

And two rulings: changing the setting on a series that already has chapters **regroups the
existing chapters**, and heading-made volumes that a regroup leaves empty are **kept**, not
deleted.

## Goals

1. Each series has a "Volumes from syosetu headings" setting: **every heading** (today's
   behaviour, the default), **only headings starting with a given marker**, or **off**.
2. The fetch dialog offers that setting above the chapter list, with the markers this series'
   headings actually use.
3. Fetches follow the saved setting. Chapters under headings that don't start a volume go into
   the volume of the most recent heading that does.
4. Changing the setting when the series has chapters shows what will change and, on confirm,
   moves the existing chapters to match.
5. The Volumes tab can select several volumes and merge them into one, keeping the chosen
   volume's details; later fetches and regroups for any of the merged headings land in it.

## Non-goals

- Hiding or collapsing empty heading-made volumes. They're listed like any other volume (count
  0) and deleted by hand.
- Undo for merge or regroup. Both confirm first.
- Two-level volumes (a day containing arcs). Only one heading kind starts volumes.
- Changing the setting anywhere except the fetch dialog (the choices need the loaded index).

## Anti-goals

- Moving chapters the owner put into a volume they made by hand. Regroup only touches chapters
  in No volume or in heading-made volumes.
- Deleting volumes during a regroup, or losing a renamed heading-made volume's title or EPUB
  details when the setting changes back and forth.
- Any change to a series with no syosetu headings, or to fetch behaviour while the setting is
  left at "every heading".

## Data model

**`series`** gains three columns:

| column | type | notes |
|---|---|---|
| `syosetu_volume_mode` | `Text`, not null, default `'all'` | `'all'`, `'marker'` or `'off'` |
| `syosetu_volume_marker` | `Text`, not null, default `''` | one character; required when mode is `'marker'`, else `''` |
| `syosetu_headings` | `JSONB`, nullable | the index's heading sequence from the last read: `[[first_num, heading], …]` in index order; `null` = never read |

`syosetu_headings` is written whenever the fetch job or a regroup reads the index (the chapter
list `GET` doesn't write). A chapter's heading is the entry with the greatest `first_num` ≤ its
number; chapters before the first entry have none. Keeping the whole sequence, not a heading per
chapter, matters: under a marker, a chapter's target depends on the headings before it, including
ones whose chapters were never fetched. Not exposed in the API.

**`volume_syosetu_groups`** (new) replaces the single `volumes.syosetu_group` column, because a
merged volume stands for several headings:

| column | type | notes |
|---|---|---|
| `id` | `Integer` PK | |
| `series_id` | FK `series.id` `ON DELETE CASCADE`, not null | for the unique key |
| `volume_id` | FK `volumes.id` `ON DELETE CASCADE`, not null, indexed | |
| `heading` | `Text`, not null | |

Unique `(series_id, heading)`, named `uq_volume_syosetu_groups_series_heading`. A volume is
"heading-made" when it has at least one row here.

Migration: autogenerate from the models, then copy every non-null `volumes.syosetu_group` into
the new table before the column is dropped. That data step is hand-written (it can't be
autogenerated); the schema part must come from autogenerate as usual. Downgrade copies one
heading per volume back (the lowest `id`) and drops the table.

## Which heading starts a volume

All of this is pure, in a new module `api/core/syosetu_volumes.py` (no DB), with unit tests.

**Marker of a heading:** its first character after leading whitespace, when that character's
Unicode category is a symbol or punctuation (`S*` or `P*`: `★` So, `◇` So, `◎` So, `※` Po).
Letters, digits, kana and kanji are never markers.

**Markers offered** for a series: markers that start at least two headings in the index, in
first-appearance order, each with its heading count. `GET /series/{id}/syosetu/chapters`
returns them alongside the chapters (see API), so the dialog doesn't recompute them.

**Starting headings:** under `'all'`, every heading; under `'marker'`, headings whose marker is
`syosetu_volume_marker`; under `'off'`, none.

**Target of a chapter:** walk the index in order, remembering the most recent *starting*
heading; each chapter's target is that heading, or `null` (No volume) if none has appeared yet.
Under `'all'` this is exactly today's rule. A chapter's target depends on the whole index, so the
fetch job computes targets from the full index it already reads, not only the chapters being
fetched.

The function takes the heading sequence (`[(first_num, heading)]`), the chapter numbers to place,
and `(mode, marker)`, and returns `{num: target_heading | None}`. Both the fetch job and regroup
call it with the stored `syosetu_headings`, so they always agree.

## Volume for a target heading

Look up `volume_syosetu_groups` by `(series_id, heading)`. If found, that volume. Otherwise
create a volume after the existing ones titled after the heading (suffix ` (2)`, ` (3)` … while
the title is taken, as today) and insert the group row. This replaces `group_volume` in
`api/fetch_job.py`.

When the volume naming design (`2026-10-21-volume-naming-design.md`) lands, "titled after the
heading" becomes kind `''`, index null, subtitle = heading, and the clash rule follows its
uniqueness for no-index volumes (suffix the subtitle). Whichever of the two lands second makes
that adjustment.

## Fetching

Unchanged except: the job saves the heading sequence it read to `series.syosetu_headings`, and
targets come from that sequence and the setting (above). Chapters already in the series are still
never moved by a fetch.

## Regrouping

`POST /series/{id}/syosetu/volume-headings`, body `{mode, marker, apply: bool}`:

1. Validate: series is the caller's and has a `syosetu_url` (404 / 422 as the other syosetu
   routes); mode is one of the three; marker is one S/P character when mode is `'marker'`, and
   must be `''` otherwise (422).
2. 409 if a `syosetu_fetch` job for the series is queued or running (same check as
   `POST .../syosetu/fetch`).
3. If `series.syosetu_headings` is null (series fetched before this feature), read the index once
   (same `_slot()` and error mapping as `GET .../syosetu/chapters`) and store the sequence. This
   runs on preview too; it records syosetu's facts and nothing else.
4. Compute each chapter's target from the sequence by its `series_order` (a syosetu series keeps
   syosetu's numbers).
5. A chapter **moves** only if its current volume is null or heading-made, and its target
   volume differs. Chapters in hand-made volumes stay put. Mode `'off'` sends every movable
   chapter to No volume. (A chapter you dragged from one heading-made volume to another counts as
   movable and goes back to its target.)
6. `apply: false` returns the preview and saves nothing else:
   `{volumes_created, chapters_moved, volumes_emptied}` (`volumes_emptied` = heading-made
   volumes that hold chapters now and would hold none afterwards).
   `apply: true` saves the mode and marker, creates the needed volumes, moves the chapters,
   runs `arrange()` (a no-op for syosetu numbering, kept for consistency), and returns the same
   counts. No volume is ever deleted.

A series with no chapters takes the same route; the counts are all zero, so the dialog saves
without asking.

## Fetch dialog

`web/src/library/SyosetuFetch.tsx`, after the chapter list loads, when the index has at least
one heading:

- A "Volumes from syosetu headings" select: "Every heading", one "Only headings starting with
  ★ (14 headings)" entry per offered marker, and "Off". It shows the series' saved value.
- Changing it calls the endpoint with `apply: false`. If every count is zero it applies at once.
  Otherwise a `ConfirmDialog` says, for example, "Creates 20 volumes and moves 1,483 chapters.
  78 volumes will be left empty; they're kept so switching back finds them." Confirm applies;
  cancel restores the select. The select is disabled while either call runs.
- After applying, invalidate the library queries (`invalidateLibrary`).

A saved marker the current index no longer uses still shows as a choice (with "0 headings") so
the select never lies about the saved value.

## Merging volumes

`POST /series/{id}/volumes/merge`, body `{volume_ids: [int], into: int}`:

- At least two distinct ids, every one a volume of this series (404 for a series that isn't the
  caller's; 422 for ids not in it), `into` among them (422).
- Every chapter of the other volumes gets `volume_id = into`. Their `volume_syosetu_groups` rows
  are re-pointed to `into`. The other volumes are deleted. `into` keeps its own title and EPUB
  fields.
- `arrange()` then runs. For a non-syosetu series its stable sort keeps the merged chapters in
  their previous reading order inside the merged volume; a syosetu series keeps its numbers.
- Returns the surviving `VolumeOut`.

Volume covers are the first chapter cover in the volume (`firstCover` in
`web/src/library/volumeGroups.ts`), so covers travel with their chapters; nothing to carry over.

**UI**, in the Volumes tab's volume list (`web/src/library/VolumeList.tsx`):

- A "Select" button above the list turns on selection: each volume gets a checkbox ("No
  volume" doesn't). Shift-click selects the range from the last ticked volume, for merging runs.
  "Done" leaves selection.
- With two or more ticked, a bar shows "Merge N volumes". It opens a dialog: "Keep the name and
  details of:" with a radio per ticked volume (default: the first in list order), and the note
  "The other N−1 volumes are deleted; their chapters move into it." Confirm calls the endpoint,
  then selects the survivor.
- Selection mode disables chapter drag-and-drop onto volumes, so a click can't do two things.

When the volume naming design lands, "name and details" means kind, index, subtitle and EPUB
fields; nothing else changes.

## API changes

- `IndexChapter` is unchanged. `GET /series/{id}/syosetu/chapters` becomes
  `{chapters: [IndexChapter], markers: [{marker, headings}]}` (the dialog is its only caller), and
  `SeriesOut` gains `syosetu_volume_mode` and `syosetu_volume_marker` so the dialog knows the saved
  value. Neither field is writable through `PATCH /series`; only the new endpoint sets them.
- New: `POST /series/{id}/syosetu/volume-headings`, `POST /series/{id}/volumes/merge`.
- Regenerate `web/src/api/schema.d.ts` (`npm run gen:api`). The existing tests that read the
  chapter list as a bare array (`tests/test_scrape_api.py`) move to `body["chapters"]`.

## Tests

- `api/core/syosetu_volumes.py`: marker detection (symbols in, kana/kanji/digits out, leading
  whitespace), offered markers (≥2 rule, order, counts), targets under all three modes including
  chapters before the first starting heading.
- Fetch job: marker mode sends chapters under non-starting headings to the previous starting
  heading's volume, including when that heading's own chapters weren't fetched; off creates no
  volumes; `syosetu_headings` is stored; existing chapters still never move.
- Regroup: preview writes nothing but the heading sequence; 409 while a fetch runs; apply moves
  only chapters in No volume or heading-made volumes; hand-made volumes untouched; emptied
  volumes kept; switching back reuses the kept (renamed) volumes; a series fetched before this
  feature reads the index once; validation 422s; another user's series 404.
- Merge: chapters and group rows move to the survivor; others deleted; survivor keeps its
  fields; reading order kept in a non-syosetu series; a later fetch of a merged heading lands in
  the survivor; validation 422s / 404.
- Migration: existing `syosetu_group` values arrive in `volume_syosetu_groups`; downgrade works.
- vitest: the range-select helper for the volume list.
- One Playwright flow is optional; the dialog logic is thin over the endpoints.

## Calls I made (not the owner's)

- The setting lives in the fetch dialog only; the Settings tab doesn't show it.
- A marker is one leading symbol/punctuation character used by at least two headings.
- The heading sequence is stored on the series (not per chapter), and regroup's preview may store
  it (a write) so applying needs no second index read.
- Regroup re-reads the index only when no sequence is stored; otherwise it uses the last fetch's.
- A regroup never moves chapters out of hand-made volumes.
- Merge's default survivor is the first ticked volume in list order; shift-click range select.
- Selection mode turns off chapter drag-and-drop.
