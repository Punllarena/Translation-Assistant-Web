# Series glossaries (retire profiles) — design

## Intent

A glossary holds the names, terms and honorifics of one story. Today it lives in a
**profile**, and each series points at a profile (`series.profile_id`). Several series can
share one profile, and the editor and Series → Tools both ask which profile to use. In
practice a glossary belongs to exactly one series, so choosing a profile is a step that
does nothing useful and can only go wrong, such as the wrong story's names being applied.

This change makes the glossary part of the series and removes profiles completely.

## What a profile holds today, and where each piece goes

| Piece | Today | After |
|---|---|---|
| Glossary (`glossary`) | per profile | **per series** |
| Custom spellcheck words (`custom_words`) | per profile | **two layers: account-wide + per series** (user's choice, option B) |
| Parse characters (`profiles.parse_chars`) | per profile | **one user setting**, `parse_chars` |
| `is_default`, the `profile_used` setting, the editor's profile picker, `editor_profile()`'s fallback chain | exist | **removed** |
| `profiles` table, `series.profile_id`, `/profiles` API, `/settings/profiles` page | exist | **removed** |

Spellcheck accepts a word if it appears in either the account-wide list or the series' own
list. The account-wide list holds the user's general vocabulary ("senpai", "isekai", British
spellings). The series list holds that story's own spellings and romanised names.

## Goals

- The editor, MT, phrase suggestions and batch import all use the chapter's own series
  glossary. No profile is chosen anywhere.
- A series' glossary and its word list are edited on the series page.
- The account-wide word list and parse characters are edited in Settings.
- Existing data survives the migration. Every series ends up with the glossary and words the
  editor applies to it today.
- The `ta.db` import keeps working with desktop databases, which still have profiles.

## Non-goals

- Sharing one glossary between several series, or linking a sequel's glossary to its
  original. Each series has its own copy. The CSV import already exists for seeding.
- Glossary CSV export, and copying a glossary from one series to another. These are possible
  later additions.
- Per-series parse characters.
- Any change to the desktop app.

## Anti-goals

- A chapter showing another series' glossary terms. This is the failure the change exists to
  remove.
- Silently losing glossary entries or words during the migration (see *Unused profiles*).
- An empty glossary appearing in a series that has one today. The migration must follow the
  same fallback the editor uses now, not only `series.profile_id`.

## Data model

**`glossary`**: `profile_id` is replaced by `series_id`
(`ForeignKey("series.id", ondelete="CASCADE")`, NOT NULL, indexed). The unique constraint
becomes `(series_id, phrase)`. `sort_order` and the rest stay as they are.

**`custom_words`**: `profile_id` is replaced by `user_id`
(`ForeignKey("users.id", ondelete="CASCADE")`, NOT NULL, indexed) and `series_id`
(`ForeignKey("series.id", ondelete="CASCADE")`, nullable, indexed). `series_id IS NULL` is the
account-wide list. A word is unique ignoring case within its list, which takes two partial
unique indexes, the same pattern as `uq_volumes_kind_*`:
- `uq_custom_words_user_lower_word` on `(user_id, lower(word)) WHERE series_id IS NULL`
- `uq_custom_words_series_lower_word` on `(series_id, lower(word)) WHERE series_id IS NOT NULL`

The same word may appear in both lists. That is harmless.

**`series`**: drop `profile_id`. `Series` gains `glossary` and `custom_words` relationships
with `cascade="all, delete-orphan"`, so deleting a series takes its glossary and words with it.

**`profiles`**: the table and the `Profile` model are dropped. `User.profiles` goes with them.

**Parse characters**: these become the user setting key `parse_chars`, a string in the same
space-separated format. When the key is unset or not a string, the editor uses
`DEFAULT_PARSE_CHARS`. An empty string is a real choice meaning "don't split", as it is
today, so the Settings → Editor form may save it. No server-side validation is added, since
`PUT /settings` stays free-form (builder's call, confirmed in review). That
constant moves from `api/schemas/profiles.py` to `api/core/text.py`, next to
`split_parse_chars`.

## Migration

This is one Alembic revision. The schema parts are autogenerated (per CLAUDE.md, fix the
model and regenerate). The data steps are written by hand inside `upgrade()`, between adding
the new columns and dropping the old ones. In order:

1. Add `glossary.series_id` and `custom_words.user_id` / `series_id` as nullable.
2. **Resolve each series' profile** the way `editor_profile()` does today when no explicit
   choice is given: `series.profile_id`, else the user's `profile_used` setting if it names one
   of their profiles, else their `is_default` profile, else their oldest profile (lowest id).
   A user with no profiles resolves to none.
3. **Glossary**: for each series with a resolved profile, insert a copy of that profile's
   glossary rows with `series_id` set, keeping `sort_order`. Then delete the original
   profile-keyed rows. Series that shared a profile each get their own copy.
4. **Words**: for each series with a resolved profile, insert a copy of that profile's words
   with `series_id` set and `user_id` taken from the series. The account-wide list starts
   empty, because which words are general is the user's call, not something to guess.
5. **Parse characters**: for each user with a profile, take the parse characters of the
   profile the editor falls back to *without* a series (`profile_used` → `is_default` →
   oldest). If they differ from `DEFAULT_PARSE_CHARS`, write them as that user's
   `parse_chars` setting.
6. Delete every user's `profile_used` setting row.
7. **Unused profiles**: see *Unused profiles* below. This runs before any profile-keyed row is
   deleted, so in practice it happens alongside step 3.
8. Make `glossary.series_id` and `custom_words.user_id` NOT NULL, create the new constraints
   and indexes, drop the old ones, drop `profile_id` from all three tables, and drop `profiles`.

`downgrade()` recreates the schema. It creates one profile per series, named after the series
(truncated to 120 characters), and moves that series' glossary and words into it. Account-wide
words go to a profile named `default` with `is_default=true`, which is also created for users
with no series. `series.profile_id` points at the new profile. A per-series round trip is
lossless, but a shared profile comes back split. That is acceptable for a downgrade.

## API

All new routes are built with `api_router()`, fetch rows through `scoped()`, and follow the
existing delete rules: key-addressed word deletes are idempotent 204, and a foreign series id
is 404.

**Glossary**: the router prefix changes from `/profiles/{profile_id}/glossary` to
`/series/{series_id}/glossary`. The same four endpoints remain (`GET`, `PUT` the whole list,
`POST` one phrase, `POST /import` CSV), with unchanged bodies, limits and upsert rules.
`import_pairs(db, series_id, text)` keeps its shape.

**Words**:
- `GET /words`, `PUT /words/{word}`, `DELETE /words/{word}`: the account-wide list.
- `GET /series/{series_id}/words`, `PUT /series/{series_id}/words/{word}`,
  `DELETE /series/{series_id}/words/{word}`: the series list.
- These keep the current `Word` path rules (no whitespace or `/`, at most 120 characters) and
  idempotent PUT (a word already present in any letter case is left alone). The current
  `/profiles/{id}/words` routes are removed.

**Spellcheck**: `POST /spell/check` takes `series_id: int | None` instead of `profile_id`. The
custom set is the account-wide words plus, when `series_id` is given (owned, else 422 via
`owned_ref`), that series' words.

**Editor lines**: `GET /documents/{id}/lines` loses the `profile_id` query parameter.
`editor_context()` reads the glossary of `doc.series_id` and the user's `parse_chars` setting.
`editor_profile()` is deleted. `DocumentLines` loses `profile`, since the client already knows
the series from the document.

**MT**: `GET /mt/stream` loses `profile_id`. `display_line()` follows `editor_context()`.

**Phrase suggestions**: `SuggestRequest` loses `profile_id`. Known phrases are always the
series' own glossary.

**Series**: `SeriesCreate`, `SeriesUpdate` (and its `NULLABLE` set) and `SeriesOut` lose
`profile_id`.

**Batch TXT import**: the single CSV is upserted into the target series' glossary. No profile
is created or named after the file. `BatchImportOut.profile_id` is replaced by
`glossary: ImportResult | None`, which is null when no CSV was imported.

**Accounts**: `POST /setup/admin` and `/auth/accept-invite` stop creating a `default` profile.

**Removed**: the `profiles` router and schemas, and `ProfileOut` in `api/schemas/lines.py`.

## `ta.db` import

Desktop databases still have `profiles`, `glossary` and `custom_words` keyed by profile, and
`series_profiles.profile_name`. The importer reads profiles into memory instead of writing
them:

- Each **newly created** series gets a copy of its desktop profile's glossary and words. The
  profile is found by `series_profiles.profile_name`. If that is empty or unknown, the desktop
  `is_default` profile is used, else the oldest. Series that already exist in the account are
  left alone, as today.
- **Parse characters**: if the user has no `parse_chars` setting, it is set from the desktop
  default profile's value, when that differs from `DEFAULT_PARSE_CHARS`.
- The current skip, "its profile was not imported", goes away because profiles are no longer
  rows that can fail. A series whose `profile_name` is missing from the source still imports,
  with an empty glossary and a report message.
- The report stops counting `profiles`. `glossary` and `custom_words` count the copies
  written. A dry run still writes nothing.
- Unused desktop profiles follow *Unused profiles* below. "Unused" counts copies made by this
  import only. If every series in the file already exists, the desktop default profile is
  unused and becomes its own series when it has entries. In a dry run the report counts these
  series like any other.
- `tadb_schema.py` keeps the desktop column sets, since they describe the source.
  `tadb_rows.py` must stay under ~400 lines. Split out a `tadb_glossary.py` if it grows past
  that.

## SPA

**Series page** (`/series/:id`): a new **Glossary** tab
(`?tab=glossary`, between Volumes and Tools) holds:
- the existing `GlossaryTable`, now keyed by series id: query key `["glossary", seriesId]`,
  with save, CSV import, reorder, the unsaved-edits guard and the route blocker moved over from
  `ProfilesPage`;
- below it, **Series dictionary**: this series' word list with add and remove.

**Tools tab**: `PhraseSuggestions` loses its profile picker and adds terms to the series
glossary. `SeriesTools` and `SeriesPage` lose `defaultProfileId`.

**Settings tab** of the series: the Profile select is removed.

**Settings → Profiles** is replaced by **Settings → Editor** (`/settings/editor`, nav label
"Editor"). It holds:
- **Parse characters**: the form moved from `ProfilesPage`, saving the `parse_chars` setting
  through `PUT /settings`;
- **Dictionary**: the account-wide word list with add and remove, with a hint that these apply
  to every series.

`/settings/profiles` redirects to `/settings/editor`.

**Editor**:
- The Profile select and `onProfile` are removed. `EditorPage` drops its `profileId` state and
  the `profile_used` write. The lines query key no longer includes a profile.
- `useSpell(seriesId, texts)` sends `series_id`.
- `MtPanels` loses `profileId`.
- Add phrase (`PhraseDialog`) posts to `/series/{series_id}/glossary` and invalidates
  `["glossary", seriesId]` and `["document"]`. The "No profile to add phrases to" notice is
  removed, because every chapter has a series.
- **Add to dictionary**: the spell menu offers two items, *Add “x” to this series* and *Add “x”
  for all series*. The `add_word` keyboard action adds to the series list, which is the common
  case. The notices name the list ("Added “x” to the series dictionary").

**Library import**: the `ImportTadb` hint says "glossaries, series and chapters" with no
mention of profiles.

## Unused profiles (decided)

A profile is **unused** when its glossary and words were copied to zero series. This covers
profiles no series links to and that aren't the fallback, the `default` profile of an account
with no series (every account gets one at signup), and in the `ta.db` import a desktop
profile whose series all already existed. The same rule applies in the migration and the
import:

- **Empty** (no glossary entries and no words): dropped. Nothing is lost.
- **Non-empty**: becomes a new series with no chapters, titled after the profile, holding a
  copy of its glossary and words. The user can rename or delete it later. If that title is
  already taken in the account, ignoring case, append ` (glossary)`, then ` (glossary 2)`,
  ` (glossary 3)` and so on until it is free (builder's call on the exact suffix; it only has
  to be unique and recognisable). The new series gets the default values for every other
  column, has no syosetu URL and no volumes, and is placed the way `POST /series` places one.
- The migration does this in SQL inside `upgrade()`. The import does it through the same code
  path that creates its other series, so a dry run writes nothing and Cancel rolls it back.

Nothing is dropped silently. A non-empty profile always lands in a series.
