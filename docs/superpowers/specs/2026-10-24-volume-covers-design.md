# Volume covers and the series cover

## Intent

A Syosetu web novel often gets a publisher later, and each printed volume then has real
cover art (example: novel18 n6273id → 一迅社ノベルス, amazon.co.jp/dp/4758096058). The user
wants to attach that art to the matching volume, by uploading a saved file or by pasting the
address of an image found online, and have it used wherever the app uses covers. They also
want to choose which volume's cover stands for the whole series.

Today a cover is an image row on a chapter (`DocumentImage.is_cover`), and every consumer
goes looking for "the first chapter cover it finds". That fits an EPUB whose first chapter
carries the cover; it does not fit a web novel whose chapters were never in a book.

## Decisions (the user's)

- **The volume is the single home for covers.** Chapter-level covers go away; existing ones
  are migrated.
- **Upload or link.** A link is downloaded once and the app keeps its own copy; it never
  hotlinks.
- **Direct image addresses only.** A link that answers with a web page (an Amazon product
  page, say) is refused with a clear error telling the user to copy the image address
  instead. No page scraping (no og:image).
- **The series cover is a choice of volume**, made by the user.

## Goals

1. Upload, replace (by link or file) and clear a volume's cover in the Volume details dialog.
2. Choose which volume's cover is the series cover; the Library bookshelf shows it.
3. Every existing cover consumer reads the volume cover instead of a chapter cover.

## Non-goals

- Covers on chapters, on loose ("No volume") chapters, or on a series with no volumes.
- Cropping, resizing or editing covers in the app (WordPress publish still shrinks as today).
- Reading a cover out of a product page, or searching for covers.
- A series cover that is not one of its volumes' covers.

## Anti-goals

- Losing any existing image during the migration.
- Publishing an image that was not published before the migration.
- Fetching a link that reaches a private or local address (SSRF).

## Data model

- New table `volume_covers`: `id` PK, `volume_id` FK → `volumes.id` ON DELETE CASCADE,
  **unique**, `src_path` text (original name or URL path tail, for EPUB file naming), `data`
  bytea, `created_at`. Replacing a cover deletes the row and inserts a new one, so the id
  changes and an immutable image URL stays correct.
- `volumes.is_series_cover`: boolean, default false, with a partial unique index on
  `series_id` where it is true, so a series has at most one chosen volume. (Planned as
  `series.cover_volume_id` first; a flag on the volume avoids a circular foreign key
  between `series` and `volumes`, and deleting the volume clears the choice by itself.)
- `document_images.is_cover` is **dropped** after the data migration.
- Effective series cover = the chosen volume's cover if it has one, else the cover of the
  first volume by `volume_order, id` that has one, else none. A chosen volume without a
  cover therefore falls back too; the choice is kept (it comes back when that volume gets a
  cover).

## Migration (data)

One Alembic revision, autogenerated for the schema changes, with the data step added between
creating `volume_covers` / `volumes.is_series_cover` and dropping `is_cover`:

1. For each volume, the cover row of its first chapter (by `series_order, id`, then image
   `anchor_position, id`) that has `is_cover` becomes the volume's `volume_covers` row
   (same bytes and `src_path`).
2. Every other `is_cover` row (later covers in the same volume, covers on loose chapters)
   stays in `document_images` as an ordinary image with `exclude_export = true`, so the art is
   kept and visible in the editor but never published or exported.
3. The migrated rows that became volume covers are deleted from `document_images`.
4. `volumes.is_series_cover` starts false everywhere (fallback = today's bookshelf behaviour
   for the first volume).

Downgrade: recreate `is_cover`, and move each volume cover back onto the volume's first
chapter as a cover row (best effort; the excluded former covers stay ordinary images).

## API

All on `api_router()`, tenancy via `scoped()`.

- `PUT /volumes/{id}/cover` — multipart `file`; ≤ 10 MiB (`read_capped`); `sniff_image` must
  say PNG/JPEG/GIF/WebP, else 415. Replaces any existing cover. Returns the cover (`id`).
- `POST /volumes/{id}/cover/url` — JSON `{url}`. The server downloads it:
  - `check_user_url(url, allow_private=False, label="image")` before the request and on every
    redirect hop (event hook, as `api/core/scrape.py` does), at most 3 redirects;
  - timeout ~20 s, streamed with a 10 MiB cap (stop reading past it → 413);
  - the bytes must sniff as PNG/JPEG/GIF/WebP. If they don't and the response
    `Content-Type` is HTML, answer 422 "That link is a web page, not an image. Open the
    image, right-click it and copy the image address." Other non-images: 415.
  - Non-200 answers and network errors: 502 with the host and status, no body echoed.
  - The `httpx.Client` is an injected seam (like `api/routers/wp.py`); tests use
    `httpx.MockTransport` and never touch the network. Runs in the threadpool (sync route).
  - `src_path` = last path segment of the URL (sanitised) or `cover.<ext>`.
- `DELETE /volumes/{id}/cover` — 204, idempotent for an owned volume with no cover.
- `GET /covers/{cover_id}` — the bytes, same headers and sniffed media type as
  `GET /images/{id}` (immutable cache, `nosniff`, `Vary: Cookie`); owned via
  volume → series → user; 404 otherwise.
- `VolumeOut` gains `cover_id: int | null` (no bytes loaded).
- `VolumeOut` gains `is_series_cover: bool`.
- `PUT /series/{id}/cover-volume` — JSON `{volume_id: int | null}`; the volume must be in
  the series (422 otherwise); sets the flag on it and clears it on the others (null clears
  the choice). Returns 204.
- Removed: `PUT`/`DELETE /documents/{id}/cover`; `has_cover` / `cover_image_id` from
  `DocumentListItem`; `is_cover` from `ImageOut`.

## Consumers

- **EPUB import** (`api/routers/epub.py`): the book's cover becomes the volume's cover if
  the volume has none (today's "only if no cover in the volume" rule, moved).
- **EPUB export**: the volume's cover.
- **Illustrations publish** (`publish.volume_images`, `illustrations.upload` /
  `has_images`): the cover is the volume's cover; inline images are the volume's images
  not excluded from export.
- **WordPress chapter publish** (`publish.chapter`): the series' effective cover rides on
  chapter 1 (`chapter_number(...) == 1`, which skips the Illustrations chapter), as the
  cover does today. That cover may come from a later volume, or exist where chapter 1 never
  had one; that is intended (the anti-goal about newly published images is about the
  leftover covers that become excluded images). Choosing a new series cover does not
  re-publish anything: WordPress shows it after chapter 1 is next published. The SPA says so
  in a hint next to "Use as series cover" (no re-publish button).
- **Volume merge** (`merge_volumes`): the kept volume keeps its cover; if it has none, it
  takes the cover of the first merged-away volume (by `volume_order, id`) that has one; the
  other merged-away covers are deleted with their volumes. The merge dialog says
  "Only one cover is kept." when more than one of the selected volumes has a cover. If a
  merged-away volume was the series cover choice, the choice moves to the kept volume.
- **Volume delete**: the cover is deleted with the volume (cascade); the delete confirmation
  mentions it when the volume has a cover.
- **Illustrations merge** (`illustrations.merge_into`): the cover special case goes away.
- **ta.db import** (`api/core/tadb_rows.py`): applies the migration rule: the first
  desktop cover per volume becomes the volume cover; others become excluded images; loose
  chapter covers become excluded images.
- **Editor**: the Cover badge on image cards goes away.

## SPA

- **Volume details dialog** (`VolumeDetails.tsx`): a Cover section above the name fields:
  the current cover (or the title tile), "Upload…" (file picker), an image-address field
  with "Fetch", "Clear", and a "Use as series cover" checkbox (or "Series cover" state when
  it already is). Each cover action applies immediately (own request, own busy state and
  error line); it does not wait for Save, and Cancel does not undo it.
- **Volume ⋯ menu** (`VolumePane.tsx`): "Use as series cover" when the volume has a cover
  and is not already the choice.
- **Volume list / pane header** (`volumeGroups.ts`, `VolumeList.tsx`, `VolumePane.tsx`):
  the volume's own `cover_id` (served from `/api/covers/{id}`); the "No volume" group has none.
- **Library** (`shelf.ts`): `seriesCards` picks the effective series cover from the
  volumes list (`is_series_cover`, `cover_id`) (pure function, unit-tested); `SeriesCards.tsx`
  loads `/api/covers/{id}`.
- **Chapter menu** (`ChapterMenu.tsx`): "Set cover…" and "Clear cover" removed.
- `npm run gen:api` after the API changes.

## Constraints

CLAUDE.md rules apply: commit at the route boundary (`flush()` only), `scoped()` tenancy
(404 for foreign ids), autogenerated migration with every model imported in
`api/models/__init__.py`, modules under ~400 lines (`api/routers/volumes.py` is at 304, so
the cover routes and the URL download likely go in a new `api/routers/covers.py` and
`api/covers.py`), env-only config, no live network in tests.

## Builder's calls (mine, not the user's)

- Separate `volume_covers` table rather than bytea columns on `volumes`, so listing volumes
  never drags image bytes and the cover id doubles as a cache key.
- Leftover chapter covers become excluded images rather than being deleted.
- A chosen series cover is remembered even while its volume has no cover; deleting the volume
  clears it (the flag goes with the row).
- No admin override for private addresses on cover links (unlike MT/WordPress URLs);
  tests patch the check.
- 10 MiB cap, 3 redirects, ~20 s timeout for link downloads.
- Cover actions in the dialog apply at once rather than on Save.
- Merge keeps one cover (the kept volume's, else the first merged-away one); delete takes the
  cover with it. Both say so in their dialogs.
- A new series cover reaches WordPress on chapter 1's next publish; a hint says so, no
  re-publish prompt.
