# Volume Illustrations Chapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** EPUB import splits chapters by table of contents, image-only chapters become one first-in-volume Illustrations chapter outside chapter numbering, and publishing that chapter replaces the volume "Publish illustrations" action.

**Architecture:**
- **Reader.** A pure planner (`api/core/epub_runs.py`) turns spine plus TOC (with fragments) into chapters made of `Piece`s (file, start anchor, end anchor). `epub_read.py` counts and extracts over those pieces.
- **Illustrations chapter.** A boolean `documents.is_illustrations` marks the chapter. `arrange()` sorts it first in its volume, and `api/library.py` derives chapter numbers that skip it.
- **Rules.** `api/illustrations.py` owns the mark rules, the import merge, and the WordPress upload. The upload is shared by a single-publish job and the batch job.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, BeautifulSoup (html.parser), pytest; React + TanStack Query, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-24-volume-illustrations-chapter-design.md`

## Global Constraints

- No Python module over ~400 lines (`api/routers/epub.py` is 343, `api/core/epub_read.py` 388: new logic goes in new modules).
- Handlers only `flush()`. Routers are built with `api_router()`. Fetch the user's rows with `scoped()` / `owned_ref()` (404 / 422, never 403).
- Migrations are autogenerated (`alembic revision --autogenerate`). Fix the model, never hand-patch.
- Tests use `httpx.MockTransport` for WordPress (`wp_site` fixture in `tests/test_wp_jobs.py`), never live endpoints.
- Never commit text from the reference book. Fixtures are built in the test, with made-up text.
- The chapter's title is exactly `"Illustrations"`.
- After API changes: `cd web && npm run gen:api`. Run `ruff check .` and `pytest` before each commit (one pytest run at a time, `TA_DATABASE_URL` at 127.0.0.1).

## Review Focus

1. A TOC anchor on an element *inside* a paragraph (`<p><a id="x"/>Title</p>`): that paragraph starts the new chapter (Task 3 test `test_anchor_inside_paragraph_starts_with_that_paragraph`).
2. Merging two volumes that each have an Illustrations chapter: no unique-index 500. The `into` volume's chapter keeps the mark and the other is unmarked (Task 2 test `test_volume_merge_keeps_one_illustrations_chapter`).
3. Deleting the volume that holds the Illustrations chapter: the chapter survives, unmarked (Task 2 test `test_deleting_its_volume_unmarks_it`).
4. A plain one-file-per-chapter EPUB with no fragments imports exactly as before (Task 4 test `test_plain_book_is_unchanged`).
5. A scheduled batch containing an Illustrations chapter: the numbered chapters get the same slots they would without it, and the Illustrations item has `scheduled_for: None` (Task 7 test `test_batch_gives_illustrations_no_slot`).

### Task 3: TOC run planner (pure)

**Files:**
- Create: `api/core/epub_runs.py`
- Test: create `tests/test_core_epub_runs.py`

**Interfaces:**
- Produces:

```python
@dataclass(frozen=True)
class Piece:
    href: str              # zip path
    start: str | None      # element id to start at; None = top of file
    end: str | None        # element id to stop before; None = end of file

@dataclass(frozen=True)
class Planned:
    title: str
    key: str               # href, or href + "#" + fragment; what the picker sends back
    pieces: tuple[Piece, ...]

def plan_chapters(spine: list[str], toc: list[tuple[str, str, str | None]],
                  anchors: dict[str, list[str]]) -> list[Planned]: ...
def units(soup: BeautifulSoup, start: str | None, end: str | None) -> list[Tag]: ...
```

`toc` is `(title, href, fragment)` in TOC order. `anchors[href]` lists the ids the TOC references that exist in that file, in document order.

Algorithm for `plan_chapters`:
1. A fragment missing from `anchors[href]` becomes `None`.
2. On-spine entries are sorted by `(spine index, anchors[href].index(fragment), or -1 for None)`. Drop later duplicates of the same `(href, fragment)` and keep the first title.
3. Spine content before the first start is one `Planned` per file, titled after the file (`splitext(basename)`), with `key=href`. The part of the first start's file before its anchor is `Piece(href, None, fragment)`, also titled after that file.
4. Each start runs to the next start:
   - same file → `Piece(href, frag, next_frag)`;
   - otherwise → `Piece(href, frag, None)`, then whole files strictly between, then `Piece(next_href, None, next_frag)` if `next_frag` is not None.

   The last start runs to the end of the spine.
5. Off-spine TOC entries are appended in TOC order, each `Piece(href, fragment, None)`.

`units(soup, start, end)`:
- Units are `soup.find_all(["p", "image"])` in document order.
- A unit is kept when its position is at or after the start boundary and before the end boundary. Positions are indexes in the document-order list of all tags.
- A boundary is the position of the element with that id. If that element sits inside a unit, the boundary is that enclosing unit's position.
- `None` means the file's top or bottom.
