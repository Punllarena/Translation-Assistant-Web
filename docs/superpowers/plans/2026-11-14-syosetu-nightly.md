# Syosetu Nightly Check and Fetch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Once a night, refresh every eligible syosetu series' latest-update date and queue a fetch for chapters above its mark.

**Architecture:** The once-a-minute tick (moved to `api/ticker.py`) queues one `syosetu_nightly` job per user per local day after the admin's time. That job, in the general worker, reads each eligible series' index, refreshes its date/headings/checked-at, seeds or reads its mark, and enqueues ordinary `syosetu_fetch` jobs. The fetch job raises the mark.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, Postgres, httpx (`MockTransport` in tests), React + TanStack Query.

**Spec:** `docs/superpowers/specs/2026-11-14-syosetu-nightly-design.md`

## Global Constraints

- Eligible series: `syosetu_url` non-blank, `status = 'ongoing'`, `archived_at IS NULL`, `syosetu_nightly` true. Never test `source`.
- New `series` columns: `syosetu_nightly` bool not null server default true; `syosetu_fetched_through` integer null, Python `default=0`, **no** server default; `syosetu_checked_at` timestamptz null; `syosetu_check_error` text not null default `''`.
- Server settings (DB row > env > default): `syosetu_nightly_enabled` (`TA_SYOSETU_NIGHTLY_ENABLED`, `true`), `syosetu_nightly_time` (`TA_SYOSETU_NIGHTLY_TIME`, `"04:00"`, `HH:MM` 24-hour), `syosetu_nightly_tz` (`TA_SYOSETU_NIGHTLY_TZ`, `"UTC"`, IANA zone).
- New chapters = index `num > max(mark, highest series_order)`; a NULL mark is seeded by the nightly read only (`max(highest index num, highest series_order)`), queueing nothing. The mark never decreases.
- Every successful index read (nightly, fetch job, `_read_index`) sets `syosetu_checked_at` and clears `syosetu_check_error`; only the nightly job writes the error.
- Index pages are throttled only when `fetch_series_index(..., delay>0)`; only the nightly job passes a delay.
- Handlers `flush()`, never `commit()`; the tick commits its own session (sanctioned). No Python module over ~400 lines. Migrations autogenerated.
- Job kind `syosetu_nightly`, params `{"day": "YYYY-MM-DD"}`; result `{"checked", "busy", "queued": [{series_id, title, chapters, job_id}], "failed": [{series_id, title, message}]}`.

## Review Focus

- An invalid env value for `syosetu_nightly_time` / `_tz` (env bypasses the validators): the tick does nothing for syosetu and logs once, and the Ollama tick still runs — test in Task 5.
- A series archived, set On hold, flag switched off, or deleted between the tick and the job's run: skipped, because eligibility is read at run time — test in Task 4.
- A series whose `syosetu_url` was edited to something `fetch_series_index` refuses (`ValueError`): its error is recorded and the other series still run — test in Task 4.
- syosetu removed chapters so the index's highest num is below the mark: nothing queued, mark unchanged — test in Task 4.
- A zone ahead of UTC where the local date differs from the UTC date (Asia/Tokyo at 20:00 UTC = 05:00 next day): the day key is the local date — test in Task 5.

### Task 4: The `syosetu_nightly` job

**Files:**
- Create: `api/syosetu_nightly.py`
- Test: `tests/test_syosetu_nightly.py`

**Interfaces:**
- Consumes: `fetch_job.mark_read`, `fetch_job.fetch_active`, `scrape.fetch_series_index(..., delay=)`, `heading_sequence`, `jobs.enqueue`.
- Produces: `eligible_series(user_id: int | None = None) -> Select` — `select(Series)` with the four eligibility conditions, filtered to `user_id` when given (Task 5 selects distinct `Series.user_id` from it); `http_client = scrape.client` seam; `@handler("syosetu_nightly") nightly(ctx: JobContext) -> dict`. The module must be imported where handlers are registered (as `api/routers/scrape.py` imports `api.fetch_job`); import it from `api/main.py` next to the other handler imports.

Handler per series (ordered by id, `ctx.progress(i, n, series.title)` before each): skip as `busy` if `fetch_active`; read the index with the job's `http_client()` and `delay=syosetu_delay_seconds`; on `ScrapeError`/`ValueError` set `syosetu_check_error = str(exc)` (fallback the type name), append to `failed`, continue; on success `mark_read`, set `syosetu_headings = heading_sequence(index)`; NULL mark → seed and continue; otherwise compute `nums`, enqueue `syosetu_fetch` (`total=len(nums)`), append to `queued`. Final `ctx.progress(n, n, "<checked> series checked, <len(queued)> with new chapters, <len(failed)> failed")`.

Test setup: copy `site`'s pattern (fake pages for `https://ncode.syosetu.com/n1/` with chapters 1–3, `jobs.SessionLocal` swapped, `monkeypatch.setattr(syosetu_nightly, "http_client", make)`, `monkeypatch.setattr(scrape, "throttle", lambda d: None)`). Drive with `jobs.enqueue(db, me.id, "syosetu_nightly", {"day": "2026-11-15"})` + `jobs.run_next()`; the second `run_next()` then runs a queued fetch.
