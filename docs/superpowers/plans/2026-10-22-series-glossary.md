# Series Glossaries Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move each glossary into its series, split spellcheck words into an account-wide list and per-series lists, make parse characters a user setting, and delete profiles.

**Architecture:** One Alembic revision changes the schema and moves the data (glossary → series, words → series, parse characters → `parse_chars` setting, unused non-empty profiles → glossary-only series). The API re-keys the glossary and word routes from `/profiles/{id}` to `/series/{id}` and adds `/words` for the account list. Every consumer reads the chapter's own series instead of resolving a profile. The SPA gains a series Glossary tab and a Settings → Editor page, and loses every profile picker.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, Postgres, pytest; React + TanStack Query + openapi-fetch, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-22-series-glossary-design.md`

## Global Constraints

- One Alembic revision. Its `down_revision` is `'6182106ad19b'`. Schema parts are autogenerated; the data steps are hand-written module-level functions taking `conn` (the pattern of `migrations/versions/6182106ad19b_volume_naming.py`).
- Handlers only `flush()`. Every router is built with `api_router()`. Fetch owned rows with `scoped()` (404 for a foreign path id) or `owned_ref()` (422 for a foreign body id).
- Word deletes are key-addressed: idempotent 204.
- Word path rule stays `Path(min_length=1, max_length=120, pattern=r"^[^\s/]+$")`. PUT is idempotent: a word already present in any letter case is left alone.
- `DEFAULT_PARSE_CHARS = "、 。 ？ ！ 「 」 …… "`, moved to `api/core/text.py`.
- `parse_chars` setting: unset or not a string → `DEFAULT_PARSE_CHARS`. `""` is valid and means "don't split".
- The suffix for a taken title (case-insensitive) is ` (glossary)`, then ` (glossary 2)`, ` (glossary 3)` and so on.
- No Python module over ~400 lines (`api/core/tadb_rows.py` is 345 today).
- `npm run gen:api` after any API change; commit `web/src/api/schema.d.ts` with it.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tasks 1–5 are one backend change. Between them run only the test files each task names; the **full `pytest` must pass at the end of Task 5**.

## Review Focus

1. **A series with no `profile_id` today** (the editor falls back to `profile_used` → default → oldest) must keep its glossary after the migration. Pinned in Task 1 (`test_series_without_profile_gets_fallback_glossary`).
2. **An account with only the signup `default` profile, holding entries but no series** must not lose them. Pinned in Task 1 (`test_unused_nonempty_profile_becomes_series`, user with no series).
3. **A word added to one series must not be accepted in another series.** Pinned in Task 3 (`test_series_word_does_not_leak_to_other_series`).
4. **Deleting a series removes its glossary and words, not other series' rows.** Pinned in Task 2 (`test_deleting_series_cascades_glossary_and_words`).
5. **`ta.db` re-import where every series already exists** must still keep a non-empty desktop default profile as a glossary-only series, and a dry run must write nothing. Pinned in Task 5 (`test_reimport_keeps_unused_profile_as_series`, `test_dry_run_writes_nothing`).
