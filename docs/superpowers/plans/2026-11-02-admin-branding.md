# Admin Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin sets the site's brand name, logo (with optional dark-mode logo and a show-name choice) and favicon in Settings → Admin → Branding; the header, auth pages, tab title and favicon follow.

**Architecture:** Two small tables (`branding` single row; `brand_images`, one row per uploaded file, replaced by delete + insert so ids are cache-safe). A public `GET /branding` returns the name, flag and image ids; public `GET /branding/image/{id}` serves bytes with a locked-down header set. The SPA reads `/branding` through one React Query hook seeded from `localStorage` (`ta.brand`), renders a shared `Brand` component, and syncs `document.title` and the icon link.

**Tech Stack:** FastAPI + SQLAlchemy + Alembic (autogenerate), pytest; React + React Query + Vite, vitest.

**Spec:** `docs/superpowers/specs/2026-11-02-admin-branding-design.md`

## Global Constraints

- Logo types: PNG, WebP, SVG. Favicon types: PNG, WebP, SVG, ICO. No JPEG/GIF. Type is sniffed from bytes, never from filename or content type.
- Size cap 1 MiB per file, enforced in the API with `read_capped` (Caddy's existing 12 MB `@small` limit already covers the route; no Caddy change).
- Brand name: trimmed, 1–60 characters; blank means the default `Translation Assistant`.
- Show-name flag defaults `true`; it only matters when a logo exists.
- Defaults: name "Translation Assistant", header shows the 訳 mark, favicon is a static 訳 SVG in `web/public/favicon.svg`. An uploaded logo is never used as the favicon automatically.
- Image routes: `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`, `Cache-Control: public, max-age=31536000, immutable`. SVG is only ever shown through `<img>` / `<link>`, never inline.
- `/branding*` public routes are not added to `MAINTENANCE_ALLOWED`; the SPA falls back to defaults on any failure.
- Build routers with `api_router()`; handlers `flush()` only; migration is autogenerated (`alembic revision --autogenerate`); new models imported in `api/models/__init__.py`.
- CSS uses tokens only (no literal colours); dark theme is `:root[data-theme="dark"]`. No Python module over ~400 lines.
- Tests: `app_client`, `make_user(is_admin=True)`, `login`; never live endpoints. Only one pytest run at a time (see local Postgres note: set `TA_DATABASE_URL` to `127.0.0.1`).

## Review Focus

- SVG containing `<script>` / `onload`: served only with `sandbox` CSP + `nosniff`, so it cannot run when opened directly (Task 2).
- Branding request failing or slow on login/setup: pages render with defaults, never blank (Task 4).
- Whitespace-only or 61-char name: 422 / stored as default, never an empty brand (Task 1).
- SVG with a BOM, XML prolog or DOCTYPE before `<svg`: still accepted; an HTML file renamed `.svg`: refused 415 (Task 1).
- File exactly at / one byte over 1 MiB: accepted / 413 (Task 2).
- Non-admin or signed-out PUT/DELETE: 403 / 401, and the public GET never leaks anything else (Task 2).
- Dark logo uploaded without a light logo, or removed later: header falls back sensibly (Task 4).
- Reset clears the browser's `ta.brand` copy so the old name does not flash (Task 3).
- Backup → restore keeps the images byte-for-byte (Task 2).
