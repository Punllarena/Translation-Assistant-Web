# Library Filters, Sort, Archive and Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user archive series, set a status on each one, and filter and sort the Library by source, status, WordPress, archive state and seven sort keys.

**Architecture:** Four new `series` columns (`archived_at`, `status`, `source`, `syosetu_updated_at`) and two endpoints, archive and unarchive. The syosetu index scraper also reads each chapter's post date, and every chapter-list read stores the newest one. The Library does all filtering and sorting client-side: pure functions in `web/src/library/libraryQuery.ts` work over the cards it already builds, with choices kept in `localStorage`.

**Tech Stack:** FastAPI, SQLAlchemy 2, Alembic, Postgres, BeautifulSoup; React 19, TanStack Query, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-25-library-filters-sort-archive-design.md`

## Global Constraints

- Statuses: `ongoing`, `on_hold`, `dropped`, `completed`, labelled Ongoing / On hold / Dropped / Completed; the default is `ongoing`.
- Sources: `syosetu`, `epub`, `other`, labelled Syosetu / EPUB / Other; the default is `other`.
- Filters: Source (any ticked; none = all), Status (any ticked; none = all), WordPress `any|published|none` (default `any`), Archived `hide|include|only` (default `hide`). Groups combine with AND, ticks within a group with OR, and the title search ANDs with all of them.
- Sorts and default directions: Last modified ↓, Latest syosetu update ↓, Latest added ↓, Title A–Z, Progress ↓, Last published ↓, Chapter count ↓. Series with no value go last in either direction, and ties break by title. The default sort is Last modified, newest first.
- "Has published" means at least one chapter has `wp_status === "publish"`.
- `localStorage` keys are `ta.librarySort` and `ta.libraryFilters`. Bad or missing values fall back to the defaults, and every access sits in try/catch (like `viewPref.ts`).
- Archiving changes nothing except `archived_at` and Library visibility. Pickers, stats and publishing still see archived series.
- Only `syosetu_updated_at` may be written by `GET /series/{id}/syosetu/chapters` and the volume-headings preview.
- Builds on CLAUDE.md rules: routers come from `api_router()`, handlers `flush()` and never `commit()`, ids go through `scoped()` (404s), migrations are autogenerated, stylesheets use tokens only, and Python modules stay under about 400 lines.
- Test fixtures never contain real syosetu titles or text: use invented placeholders.

**Plan call (deviation from spec):** the spec asks for CHECK constraints on `status` and `source`. The repo has none anywhere and Alembic autogenerate doesn't emit them, so this plan validates with pydantic `Literal`s instead. Writes only come through the API and the importer, which both set known values.

## Review Focus

1. **Corrupt or stale stored prefs:** `ta.libraryFilters` holding bad JSON, an unknown status string, or a missing group should load as the defaults, with unknown ticks dropped, never as a blank page. Test: `libraryPrefs.test.ts` "drops unknown values and fills missing groups".
2. **Every series archived under Hide:** the Library must say they're all archived and offer "Show archived", not "No series yet". Test: `libraryQuery.test.ts` "emptyReason" returns `"all-archived"`. The e2e suite can't reach this state, because other specs own live series.
3. **A syosetu row with a revision marker, no date, or a garbled date:** parse the post date, ignore 改稿, return `None` without raising, and never move `syosetu_updated_at` to NULL. Tests: `test_core_scrape.py` `test_index_reads_post_dates_and_ignores_revisions` and `test_a_read_with_no_dates_keeps_the_stored_date`.
4. **PATCH with an unknown status or source:** a 422, never a 500. Test: `test_series_archive.py::test_unknown_status_or_source_is_422`.
5. **Sorting with missing values in both directions:** an EPUB series (no syosetu date) and a never-published series stay last when the direction flips. Test: `libraryQuery.test.ts` "keeps missing values last in both directions".

The revision marker sits in a nested `<span title="… 改稿">`; it comes after the first match, so the first match is always the post date. No element or no match gives `None`.

```ts
export type SeriesStatus = SeriesRow["status"];
export type SeriesSource = SeriesRow["source"];
export const STATUS_LABEL: Record<SeriesStatus, string>;   // Ongoing, On hold, Dropped, Completed
export const SOURCE_LABEL: Record<SeriesSource, string>;   // Syosetu, EPUB, Other
export type SortKey = "modified" | "syosetu" | "added" | "title" | "progress" | "published" | "chapters";
export type SortDir = "asc" | "desc";
export interface LibrarySort { key: SortKey; dir: SortDir }
export const SORT_LABEL: Record<SortKey, string>;          // Last modified, Latest syosetu update, Latest added, Title, Progress, Last published, Chapter count
export const DEFAULT_DIR: Record<SortKey, SortDir>;        // title "asc", all others "desc"
export const DEFAULT_SORT: LibrarySort;                    // { key: "modified", dir: "desc" }
export interface LibraryFilters {
  sources: SeriesSource[]; statuses: SeriesStatus[];
  wordpress: "any" | "published" | "none"; archived: "hide" | "include" | "only";
}
export const DEFAULT_FILTERS: LibraryFilters;              // [], [], "any", "hide"
export function filterCards(cards: SeriesCard[], f: LibraryFilters, search: string): SeriesCard[];
export function sortCards(cards: SeriesCard[], s: LibrarySort): SeriesCard[];   // new array
export function activeGroups(f: LibraryFilters): number;   // groups not at default, 0..4
export function emptyReason(all: SeriesCard[], f: LibraryFilters, search: string):
  "none" | "all-archived" | "no-match";                    // "none" = no series at all
```
